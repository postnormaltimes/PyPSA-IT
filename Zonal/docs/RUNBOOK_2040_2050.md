# Model execution and validation

Run PowerShell from the Zonal model directory. From the PyPSA-IT repository root, first run cd Zonal. Install the uv CLI first; environment creation uses the pinned Python and package versions. Gurobi requires a valid local licence, which is not distributed with the model.

```powershell
.\scripts\create_environment.ps1
.\scripts\bootstrap_data.ps1 -SourceDir '..\.data-packages\zonal-production-data-v1' -Mode A
.\scripts\validate_installation.ps1
```

For deterministic reconstruction, install the additional accepted inputs. Reconstruction is offline and creates no optimization model. It compares all twelve final UC/reference networks with the distributed pairs, including component values, hourly inputs and relevant constraints.

```powershell
.\scripts\bootstrap_data.ps1 -SourceDir '..\.data-packages\zonal-production-data-v1' -Mode All
.\.venv\Scripts\python.exe -B -m mem_model.portable_rebuild --data-root '..\.data-packages\zonal-production-data-v1' --output-root outputs/rebuild/validation
```

The canonical execution family is `final_methodology_v1` / `final_v1`. The known 2040 Base reproduction command is:

```powershell
.\scripts\run_2040_base.ps1
```

It checks the licence, then runs reference LP → verification → UC MILP → verification → fixed-commitment price LP → verification → core report → final QA → compact reference comparison. It never executes 2050. Every prerequisite must pass before the next action. Existing results are verified rather than overwritten. Allow several hours and adequate memory for the annual MILP.

For one authorized case:

```powershell
.\.venv\Scripts\python.exe -B -m mem_model.stage_b_uc2 preflight --year 2040 --scenario Base --variant final_v1
```

Subsequent actions are `run-reference`, `verify-reference`, `run-uc`, `verify-uc`, `run-price`, `verify-price`, `report` and `final-qa`, in that order. Core reporting is the default. After verification, `report --presentation` adds optional figures using the configured toolkit and geography.

All six final_v1 cases have explicit manual authorization in `config/final_methodology_execution_v1.yaml`. Execution remains restricted to one selected case and the verified reference → UC → fixed-commitment price sequence. Analytical review is independent. Historical solved results cannot replace current prepared networks.

Generated results reside under `results/final_methodology_v1` and `outputs` and are untracked. Bootstrap can be rerun safely and stops on missing or mismatched assets. A licence failure is an environment limitation and does not justify changing the solver or methodology.
