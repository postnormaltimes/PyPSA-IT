# Runtime architecture

There are exactly two executable contracts; deep research regeneration is separate.

**Path A:** repository controls + versioned path_a payload → exact prepared final UC/reference pairs → final_v1 preflight → reference LP/verification → UC MILP/verification → fixed-commitment price LP/verification → core tables/water diagnostics/final QA. stage_b_uc2 routes cases; final_methodology_networks applies integrity/authorization checks. Solves create new same-case receipts, not copied historical solved state.

**Path B:** repository controls + path_b accepted baseline/profile payload (and path_a pairs as parity references) → portable_rebuild → baseline network → P2X → UC1 decomposition → accepted UC2A overrides → zonal solar → final W/H → signed N/C → final UC and continuous-reference pair. It calls accepted transformations without replaying historical one-shot orchestration. Semantic parity compares snapshots, static/dynamic components and relevant constraints against all twelve prepared reference files. Reconstruction is non-solving.

The common 2019 chronology and inherited methodology are fixed. Horizon-specific runtime quantities, calibrated unit composition, native wind profiles, hydro mapping and external-price boundary packages remain separately selected. There is no Stage-A execution edge in Path A/B. All unique MEM rebuild inputs are tracked or bundled.

Core analytical reporting is independent of optional VIS-X1/geography. Marginal-regime production reads only validated roots belonging to the current solved/price family; missing roots yields WAITING. Presentation-only toolkit integration is configurable and separate. Legacy source-building modules/docs remain reachable evidence, but canonical runbooks do not call their developer-specific source paths.
